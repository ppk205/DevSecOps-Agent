# Validator and CVSS verification — 2026-11-04

Scope: SRS FR-50/53/56, independent decision ownership and deterministic CVSS
v4.0 arithmetic. Changes are on `feat/native-workflow-notifications` after
base `1a59e3b`, alongside the earlier OWASP reporting addition. This record does
not certify vulnerability accuracy or independent verification of metric choices.

## Confirmed defects and corrections

The original validator counted strong model records as independent support,
including a rejected model verdict described as counterevidence. The same
counterevidence could therefore satisfy confirmation thresholds. It also counted
`blocked` outcomes as demonstrations and accepted repeated/foreign evidence or
fixed-variant results without adequate scope checks. New regression controls
reproduced false confirmations before correction.

The corrected decision policy excludes model/raw-scanner records from terminal
authority, separates explicit support/counterevidence, scopes records to the
finding/run, deduplicates identities and keeps conflicting or incomplete results
unresolved. Trusted positive/counter controls still exercise terminal decisions.
Decision metadata records the policy, assessment/run identity, qualified and
ignored inputs, conflicts and actual verification outcomes. The current review
adapter does not perform independent semantic verification, and its proposals
normally remain unresolved. It does not manufacture independent flags from
confidence or textual claims. Existing human review remains available.

The old scorer used an older-style weighted formula, accepted v3 Scope under a
v4.0 prefix, omitted mandatory subsequent-system metrics and could turn missing
input into zero severity. Exact FIRST controls reproduced numerical differences.
It has been replaced with pinned FIRST MacroVector tables and interpolation.
Syntax, order, values and all eleven Base metrics are validated. Base and
contextual scores are separate; incomplete Base vectors remain unscored.

CVSSAssessment recomputes scores from its vector, including validated assignment.
The bounded loop and single-shot path preserve assumptions and safe score-error
metadata. JSON braces inside rationale no longer discard valid vectors. An
already parsed explicit verdict avoids a redundant fallback call. Run/finding
metadata and JSON reports retain the assessment and validator decision. The
dashboard/API label Base and contextual scores separately and identify legacy
calculation provenance.

## Integration, regression and remaining limits

The real Windows EXE/JSONL/provider-parser path retained a computed Base score
of 9.3 while the finding stayed unresolved and metric assumptions stayed
unverified. The synthetic provider also supplied an incorrect numeric score;
it did not become the recorded value. SQLite/finding reads and JSON exports
retained the calculation source and decision. This establishes execution and
provenance, not that the synthetic vulnerability or its metrics describe a
real target.

Tests first failed on false confirmations, counterevidence, blocked/fixed and
foreign/duplicate records, invalid threshold acceptance, wrong FIRST scores,
missing/invalid v4 metric handling, absent pipeline fields and ambiguous display.
The final focused checks pass those controls. The old verification test helper
was corrected to use its requested outcome rather than hardcoding demonstrated.
Old scorer tests using v3-style Scope and incomplete Base vectors were corrected
to valid v4 cases rather than used as evidence for the old formula.

Current independent metadata is a trusted-producer contract, not cryptographic
attestation or a semantic source verifier. Source sanitizer/authorization checks
and independent validation of CVSS metric assumptions remain incomplete.
`metric_assumptions_verified` remains false. Arithmetic alone cannot update
scanner severity or prove a finding. Historical labels, scores and artifacts
are preserved and are not recertified by this fix.

No live provider call, notification send, model download, full target scan or
held-out detection evaluation was used. Source references were fetched read-only;
conformance checking then ran offline. No dependency/lockfile, essay, previous
evidence, commit or repository history was changed for this task. See
[VALIDATOR-CVSS.md](VALIDATOR-CVSS.md) for interfaces and interpretation.
