OS command injection via unsanitized request parameter in shell=True Popen

unresolvedcritical · model-579e2e · CWE-78

request.args.get('target') flows directly into a concatenated shell command string passed to subprocess.Popen with shell=True. Any attacker who can reach this route controls the shell line, e.g. ?target=127.0.0.1;id, yielding arbitrary command execution as the app's user.

Unsafe deserialization of raw request body with pickle.loads

unresolvedcritical · model-1c9c9f · CWE-502

request.get_data() is passed straight to pickle.loads. Pickle can invoke arbitrary callables during unpickling, so a crafted body achieves remote code execution before any validation is possible. There is no allowlist, signing, or type check.

unresolvedhigh · model-54d4ad · CWE-89

The 'name' query parameter is concatenated into the SQL text instead of being bound as a parameter. A value such as ' OR '1'='1 or ' UNION SELECT ... breaks out of the string literal and alters the query, enabling data disclosure and authentication bypass.

Unsafe YAML deserialization using yaml.Loader on request body

unresolvedcritical · model-c5e393 · CWE-502

yaml.load with the full yaml.Loader constructor resolves arbitrary Python object tags (e.g. !!python/object/apply:os.system), so attacker-supplied YAML in the request body leads to code execution. yaml.safe_load is the correct call here.
